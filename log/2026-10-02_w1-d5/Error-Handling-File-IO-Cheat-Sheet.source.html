1try / except / else / finally

try:
    text = Path(path).read_text(encoding="utf-8")
except FileNotFoundError:            # SPECIFIC error
    log.warning("missing %s", path)
    return []
else:
    print("runs only if nothing raised")
finally:
    print("always runs: cleanup")

raise ValueError(f"bad file {path}") from e  # keep cause
class DownloadError(Exception): pass         # your own type

Never except: or except Exception: pass: the program carries on with bad data, fails later somewhere unrelated, and the traceback is gone.

2Rules interviewers check

Catch narrowOnly the errors you can actually handle; let the rest propagate.
Fail loudRaise early with a clear message: "month must be YYYYMM".
Keep the causeraise X from e chains the original traceback.
Custom typesWhen callers need to tell your errors apart (DownloadError).
withCloses files / connections even if an exception is raised.

4Retries: only transient errors

ErrorRetry?
Timeout, 500, 502, 503, 504Yes: the server may recover
429 rate limitedYes, after waiting (honour Retry-After)
400, 401, 403, 404No: same request fails the same way
for attempt in range(1, 4):
    try:
        return fetch(url)
    except TimeoutError:
        if attempt == 3:
            raise DownloadError(f"gave up on {url}")
        log.warning("retry %d for %s", attempt, url)
        time.sleep(2 ** attempt)       # backoff 2s, 4s

Cap the attempts, back off exponentially, log every retry, and set a timeout= on every request.

5Interview questions

Why not a bare except?It hides bugs (even typos) and the traceback; the failure appears later with no clue why.
else vs finally?else runs only if no exception; finally always runs, for cleanup.
What does with do?Calls the object's exit/cleanup (closes the file) even if the block raises.
Which errors do you retry?Transient ones (timeouts, 5xx, 429) with backoff and a cap. Never 4xx client errors.
What is idempotent?Running it twice has the same effect as once: e.g. skip the download if the file already exists.
