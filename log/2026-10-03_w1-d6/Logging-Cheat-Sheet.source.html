Python Logging Cheat Sheet

Levels, named loggers and one-time configuration: how real services tell you what happened without a debugger

Python · Week 1Modules get loggers. Only main configures.

1The setup every project uses

# downloader.py  (any module)
import logging
log = logging.getLogger(__name__)   # name = "downloader"

def download(month):
    log.info("downloading %s", month)   # lazy %s, not f-string

# main.py  (entry point ONLY)
import logging
logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s %(levelname)s %(name)s: %(message)s",
    # filename="app.log",          # file instead of console
)

basicConfig only applies on the first call. If an imported module calls it, that module decides the config for the whole program and main's call is ignored.

2Levels: pick by who needs to know

LevelUse for
DEBUGDetail for developers: full URLs, payload sizes
INFONormal milestones: started, saved 5,000 rows
WARNINGUnexpected but handled: retry 2 of 3
ERRORAn operation failed: gave up after 3 attempts
CRITICALThe program can't continue

Default level is WARNING, so info() and debug() print nothing until you lower it. Setting a level shows that level and everything above.

3Errors, files and noisy libraries

try:
    a / b
except ZeroDivisionError:
    log.exception("division failed")   # ERROR + full traceback

logging.basicConfig(filename="app.log", level=logging.DEBUG)

logging.getLogger("urllib3").setLevel(logging.WARNING)
# silence one library, keep your own code at DEBUG

Handler = where logs go (console, file, monitoring). Formatter = how they look. basicConfig sets both for you.

4Rules

Not printLogs have levels, timestamps and the source module, and can be switched off or sent to a file.
One per modulegetLogger(__name__): every line shows which file wrote it.
Lazy formatlog.info("n=%s", n): the string is only built if the level is on.
No secretsNever log API keys, passwords or personal data.
ProductionStructured JSON logs + a request ID per request (as in Aegis) so logs can be searched.

5Interview questions

Why logging over print?Levels you can turn on/off, timestamps, source module, and output to files or monitoring tools.
Why getLogger(__name__)?Each module gets a named logger: you see where a line came from and can set levels per module.
Where do you configure logging?Once, in the entry point. Libraries and modules only create loggers.
What do you log in an API client?Start/finish at INFO, retries at WARNING, final failure at ERROR, request details at DEBUG. Never secrets.
Why structured logs?JSON fields (request ID, latency, status) can be filtered and aggregated; free text can't.
