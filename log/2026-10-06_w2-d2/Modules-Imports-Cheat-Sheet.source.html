Modules + Imports Cheat Sheet

How Python finds your code, how to structure a package, and how to run and install it without import errors

Python · Week 1–2Which folder did I run from, and can Python see the package?

1How import finds things: sys.path

import sys; from pprint import pprint
pprint(sys.path)     # folders searched, IN ORDER:
# [0] folder of the script you RAN   ← key line
# ... standard library
# ... site-packages (pip / uv installs)
Moduleone .py file
Packagefolder of modules + __init__.py (can be empty)
Cacheda module runs once; later imports reuse sys.modules
Shadowingyour random.py hides the real random: never name files after libraries

python drill/logging/main.py → sys.path[0] = drill/logging/, so from mathutils import divide works but from drill.logging... doesn't.

2Import styles

import mymodule                      # mymodule.greet()
import numpy as np                   # alias
from mypackage.module1 import add    # ABSOLUTE: default
from .module1 import add             # RELATIVE: inside a package only
from mypackage import add            # works if __init__.py re-exports it
from x import *                      # NEVER: hides where names come from
Absolutedefault; explicit; PEP 8; works from any file
Relativeonly inside a package; survives renaming the package; fails in a script run directly
CircularA imports B imports A → ImportError; move shared code to a third module

3__name__, -m and -e

if __name__ == "__main__":   # run directly → "__main__"
    main()                   # imported → "mymodule": block skipped

python -m package.moduleA    # run a file INSIDE a package, from the root
python -m pip install x      # pip of THIS python
python -m pytest

pip install -e .             # editable install of MY project
                             # → importable from anywhere, edits apply live

sys.path.append("...") works but hard-codes a path: breaks on other machines and in Docker. Use -m or pip install -e . instead.

4Environments: venv + uv

python -m venv .venv               # create
.venv\Scripts\activate             # PowerShell
source .venv/Scripts/activate      # Git Bash
pip install -r requirements.txt
pip freeze > requirements.txt

uv init · uv add requests · uv add --dev pytest
uv sync                            # make .venv match uv.lock
uv run python main.py              # run without activating
pyproject.tomlwhat you asked for (ranges) + project info
uv.lockexact versions of everything, incl. sub-dependencies
.venv/never commit: machine/OS-specific, rebuilt by uv sync

5Interview questions

How does Python find a module?Searches sys.path in order: the script's folder first, then the standard library, then site-packages.
What does if __name__ == "__main__" do?Runs the block only when the file is run directly, not when it's imported.
Absolute or relative imports?Absolute by default (explicit, PEP 8). Relative only within one package.
-m and pip install -e .?-m runs a module by name from the current folder; -e installs my project editable so it imports from anywhere.
Lock file vs pyproject.toml?toml declares needs; lock pins exact versions so every machine is identical. .venv is rebuilt, never committed.
